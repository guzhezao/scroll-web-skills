# 网页制作提示词模板

先把真实视频/帧序列、海报图和产品资料交给能编辑项目的编码Agent。替换花括号字段后复制；不需要某项能力时删除对应条目。

~~~text
请用附带的产品动画，制作一个完整、独立的滚动交互产品网站。

产品/品牌：{名称、介绍与已有事实资料}。
目标：{产品介绍/预约/了解系列等}；目标访客：{人群}。
素材：{真实文件路径或可访问链接、实际视频时长和尺寸、海报、配色/口味图片}。
已有项目：{工程路径、技术栈、需要保留的页面与动效；没有就说明新建}。
视觉方向：{字体性格、主辅配色、排版密度、参考的交互特点}。

一、进入
加载画面的文字和配色对应当前产品，等待首屏必要素材。能计量资源完成度才显示对应数字，否则使用品牌加载动画。失败时给可用海报和继续浏览/重试方式，不永久卡在loading。
进入后有简短自然入场，随后交给滚动控制；入场末帧和滚动起始位置一致，不突然跳回第一帧。恢复历史位置、直接进入中段也要正确显示。

二、滚动主视觉
把实际滚动位置映射到该区域的动画进度。向下展开、停住观察、向上合回；保留原生滚动，不锁住鼠标滚轮。文字在网页中独立排版，不烧进视频。不要默认视频播放条。
章节顺序是{全貌→结构/拆解→材质或其他新信息→归位}，以真实素材的动作边界为准。每章有一条产品信息与合适停留距离，给出章节总长度和每段长度的选择理由。
素材不足就说明需要补哪段，或用已有细节图和正文接续；不要只把同一个5秒画面循环放大，或拉长空滚动。

三、完整产品内容
继续做{材料/技术/口味故事/使用场景/规格/FAQ中适用的内容}。介绍的布局与主视觉呼应，并为各产品分别设计，不机械复用同一种卡片布局。
提供{已有配色或口味}选择；点击后同步更新对应素材、文字和选中状态，切换后保留合理的滚动位置。没有素材的选项不要假装可用。
下一步操作为{实际可用的链接、锚点、联系或其他功能}。不要默认添加假购买、假支付或虚构数据。不在页尾塞其他无关案例跳转。

四、适配与质量
桌面保持大幅主视觉与清楚信息层级；手机保证主体安全区、文字可读、控件可点。加载失败、较慢设备与减少动态效果设置仍能阅读完整信息。
先检查实际视频拖动是否流畅，再选择原生video、分段素材或有内存上限的帧序列方案。只引入本项目需要的依赖，保留现有有效动画。

五、交付与验证
实际运行并验证：加载→入场→下滚→停住→上滚→后续介绍→款式选择；再检查刷新中段、快速滚动、窄屏和媒体失败。
给出源码、运行方式、真实测试范围与剩余问题。用连续操作证据说明交互，不以静态截图或“代码已写完”代替完成。不自行部署到公网。
~~~

## 实现备注：进度与时间

如果使用原生视频，先读取元数据和可用时间范围，再做映射。对于单个固定区域，可从下面的关系开始，布局变化后重新测量：

~~~text
p = clamp((scrollY - sectionTop) / (sectionHeight - viewportHeight), 0, 1)
targetTime = sourceStart + p * (sourceEnd - sourceStart)
~~~

区域高度必须大于视口高度；多片段各自使用独立的起止范围，不把例子里的时长当成实际素材。入场段若使用0到t0，滚动区从t0接续，避免两套控制器同时写时间。

浏览器设置currentTime会发起seek，seeked表示定位结束。可以保留最新目标并限制进行中的定位，完成后追上最新目标；同一时间或极近目标要跳过，不要等待一个不会发生的seeked；失败和超时须释放等待状态。平滑收敛要可终止，不能在停止滚动后继续播放整个片段。参见[MDN currentTime](https://developer.mozilla.org/en-US/docs/Web/API/HTMLMediaElement/currentTime)与[seeked](https://developer.mozilla.org/en-US/docs/Web/API/HTMLMediaElement/seeked_event)。

对[prefers-reduced-motion](https://developer.mozilla.org/en-US/docs/Web/CSS/@media/prefers-reduced-motion)提供稳定海报或低动态呈现，仍显示产品内容与控件。以上是实现约束，具体API和框架接法以目标项目及当前文档为准。
